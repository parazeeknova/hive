# Local agent acceptance

Use `devenv shell` for the commands below. These fixtures sign only on a loopback Anvil chain (31337) using its public test mnemonic. They never load production payment credentials.

Start PostgreSQL and Redis with `docker compose up --detach --wait postgres redis`. Start the isolated payment chain and facilitator with `bun packages/local/src/chain/start.ts`, then Hiveway with `bun packages/local/src/agents/serve.ts`.

Run the acceptance flows in order:

```sh
HIVE_DEMO_REVISION=$(git rev-parse HEAD) bun packages/local/src/agents/demo.ts
bun packages/local/src/agents/hosted-demo.ts
bun packages/local/src/agents/mcp-demo.ts
```

The first two flows check creator payouts per invocation on the local chain, dynamic artifact results, sales, and replay without another transfer. The MCP flow checks protocol negotiation, artifact upload, free publication, dynamic tool discovery, execution, replay, rejection of changed input, and receipt ownership. It measures 30 sequential searches and writes a one-hour buyer credential to `.hive/local/opencode-token` with mode 0600. That credential can read and invoke capabilities; it cannot publish.

## Hosted MCP connection

For everyday agent use, connect to `https://hiveway.itssingularity.com/mcp` with an `Authorization: Bearer YOUR_HIVE_API_KEY` header. Create a key at [Account settings → API keys](https://hive.itssingularity.com/dashboard?view=settings&tab=api-keys). Free capabilities do not require a wallet. The hosted service does not accept credentials generated by the local acceptance fixtures.

OpenCode v2 uses `mcp.servers.hive`. To add the hosted server:

```sh
opencode mcp add hive --url https://hiveway.itssingularity.com/mcp \
  --header 'Authorization=Bearer YOUR_HIVE_API_KEY' --global
```

Replace the placeholder with your Hive API key and keep the resulting config private. Other clients and environment-variable examples are available in the [connection guide](https://hive.itssingularity.com/docs#connect). Refresh expired keys in Account settings. Existing MCP connections may need `opencode reload`.

The local acceptance fixtures above still use a loopback server and their own disposable credentials. They do not configure a hosted account.

Check `opencode mcp list`, then run:

```sh
opencode run --model meta/muse-spark-1.3-contributor \
  'Use Hive MCP to search Free MCP echo, invoke one free echo with a new UUID idempotency_key, and repeat the same input and key to verify replay.'
```

Agents can call Hive during their own tasks. Hosted artifacts are immutable, pure JSON-in/JSON-out Wasm with CPU, memory, input and output limits. They cannot access files or networks. Server-side workflows currently compose up to four owned repository-analysis capabilities; they do not call arbitrary external agents. Free invocations produce a receipt without fabricating a blockchain settlement or creator earnings. Paid invocations require a client wallet signature per quoted call.

## Measured acceptance (2026-10-30)

Meta Muse Spark 1.3 Contributor in OpenCode successfully searched, invoked a free echo artifact, and replayed the same invocation ID and result. Paid Wasm calls with two different inputs transferred 20,000 local token units total; the repository-analysis call transferred 10,000. All replays preserved balances.

With 10,000 disposable catalog entries on this machine, the indexed search run measured 25.35 ms for a cold HTTP request. A 64-request burst at concurrency 8 measured 4.50 ms median, 5.80 ms p95, 8.15 ms maximum, approximately 1,435 requests/second during that short burst. Thirty sequential MCP searches measured 3.50 ms median, 5.05 ms p95, and 22.75 ms maximum. These are loopback development measurements, not sustained capacity or an Internet latency guarantee. The default peer rate limit still applies. The tests do not establish a speedup against another agent workflow.

Rust unit and PostgreSQL/security integration tests also run against PostgreSQL 18.6. Dodo checkout/refund behavior uses integration fixtures in test mode. Real provider payments and a deployed public Hive service require separate acceptance.

On this machine the Compose facilitator build failed because the Podman host referenced a missing `catatonit` executable. Running `bun packages/local/src/payments/facilitator.ts` directly allowed the local chain tests to continue. The pinned PostgreSQL 18.6 container started and passed integration tests.

## Hosted builder

Configure the server with all three variables (keep the key in ignored `.env.local` or the deployment secret environment):

```sh
HIVE_BUILDER_API_URL=https://api.meta.ai/v1/chat/completions
HIVE_BUILDER_MODEL=muse-spark-1.3-contributor
HIVE_BUILDER_REASONING_EFFORT=low
HIVE_BUILDER_API_KEY=YOUR_SERVER_MODEL_KEY
```

The endpoint is configurable and must accept OpenAI-compatible chat completions with JSON-object output. Reasoning effort is optional and omitted unless configured; set it only for models supporting that parameter. All three omitted disables new builds. Partial configuration fails startup. No provider key is sent to browsers or MCP clients. Meta Contributor can use prompts and responses for training, so avoid private content in task inputs.

`HIVE_BUILDER_ACCOUNT_DAILY_LIMIT` defaults to 3; `HIVE_BUILDER_GLOBAL_DAILY_LIMIT` defaults to 20. These count all accepted jobs in a rolling 24-hour window, including failures. One queued/running job per account, two generation attempts per build, a maximum of 8192 output tokens per attempt, and a 120-second timeout bound provider work. Limits are shared in PostgreSQL across replicas. They bound requests, not a precise currency spend cap. Provider billing limits remain useful.

Use `POST /v1/builds` or MCP `build_capability` with `idempotency_key`, `name`, `description`, `task`, and 1–8 `{input, expected}` examples with object inputs and outputs. Read an owned build through `GET /v1/builds/{id}` / `get_build`; `GET /v1/builds` returns the latest twenty. A publishing-scoped GitHub identity can build without a wallet. Validation compiles generated WAT inside Hive, verifies the existing Wasm ABI and sandbox, and runs every supplied example. Only passing candidates publish zero-price artifacts and capabilities, atomically with the job's final state. No shell, native compiler, imports, WASI, network or filesystem are available to generated code. JSON validators, transformations and calculations fit this runtime; external side effects need a separate runtime.

Provider credentials are checked before generation and publication. Revoked or expired Hive credentials cannot finish publication. Queued jobs survive restarts; generating jobs without an update for ten minutes fail as interrupted rather than silently repeating model calls. Job details, source and reports are owner-only. Published capability schemas and results follow normal catalog visibility. Poll `queued` / `generating` until `published` or `failed`.

To explicitly fund an isolated live-provider acceptance test, set `HIVE_TEST_DATABASE_URL` and the three builder variables, then run:

```sh
cargo run --locked -p hiveway --example hosted_build
```

This creates a temporary PostgreSQL schema, generates an integer-doubling tool, checks three supplied cases plus five unseen inputs, and removes the schema. It makes up to two real model calls. Ordinary tests use an isolated mock provider and never need the model key.
