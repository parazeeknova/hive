# Nectar workspace

`/dashboard` validates the database-backed session on the server and redirects guests to `/sign-in`. GitHub sign-in and signup share an OAuth code flow with random browser-bound state, PKCE S256, and an HttpOnly SameSite=Lax cookie. Sessions expire after 24 hours, survive reloads and service restarts, and are revoked in PostgreSQL on logout. The GitHub provider ID, rather than a mutable username, identifies the account. Provider access tokens are discarded after identity verification.

Set `GITHUB_CLIENT_ID` in Nectar and Hiveway, `GITHUB_CLIENT_SECRET` in Hiveway, and the same `HIVE_AUTH_ORIGIN` in both (local default `http://127.0.0.1:3000`). Register exactly `<HIVE_AUTH_ORIGIN>/api/auth/callback` with the GitHub OAuth app. Set `HIVEWAY_ORIGIN` for Nectar's server-to-server connection (default `http://127.0.0.1:3001`). Set `NEXT_PUBLIC_HIVEWAY_ORIGIN` at build time to the browser-accessible API/MCP origin; production images default to `https://hiveway.itssingularity.com`. The server connection may use Dokploy service DNS, while copied agent settings must use the public origin. Production uses Secure cookies and requires HTTPS. Do not put secrets in public environment variables.

Browser requests use the same-origin `/api/hiveway` proxy, which injects the server-only session credential and checks Origin for writes. Private results use no-store responses. GitHub accounts can discover capabilities, read artifact schemas, run free capabilities, and inspect their receipts. Payment and publishing permissions require a separately signed wallet credential; GitHub login never creates a payment address or authorizes spending. Wallet credentials remain in memory.

The catalog, owned listings, activity, receipts and sales use Hiveway. There is no example catalog, simulated profile, local balance or local availability override. Creator controls upload real Wasm, publish immutable definitions and prices, compose workflows, and pause/restore listings. Create forms accept the backend's JSON definitions and show validation errors and actual responses.

Sample tests accept editable JSON and execute the backend's schema validation and bounded runtime. Free capabilities are available to signed-in users; paid sample tests are creator-only. Other paid invocations use quotes and explicit x402 handoff or the existing Dodo test checkout. Dodo is test-mode accounting, not production funding. Checkout redirects never establish settlement; receipts remain authoritative. Sample tests do not create billable invocation receipts.

Validate with `bun test scripts/tests`, Nectar TypeScript checks, `cargo test -p hiveway --lib`, and lint/format checks. Full GitHub login acceptance needs a configured OAuth app and interactive provider authorization.

## Account settings

The original Profile, Agent balance, and Capabilities tabs use shared server queries. `GET /v1/account` creates or reads the authenticated identity's persistent profile; `POST /v1/account` saves display name, unique username, and avatar in PostgreSQL. GitHub identities initially use their GitHub avatar. The profile photo is displayed without edit controls. Profile data follows the GitHub account across sessions; connecting a wallet does not replace that browser account's profile.

`GET /v1/account/balance` validates the configured RPC chain and reads USDC and native holdings at a pinned block. GitHub-only sessions return an explicit unconnected wallet with a null balance. The sidebar and balance panel share cached reads. Send opens the wallet's confirmation with an ERC-20 transfer; it checks the selected wallet, network, amount, and recipient. A submitted hash is not presented as confirmed settlement. Receive and Top up show the actual wallet address; Base Sepolia includes a test faucet link. Dodo test checkouts fund individual invocations, not a custodial Hive wallet balance. Creator earnings use the existing ledger summary API and remain separate from wallet holdings.

Owned capabilities include paused listings, retain pagination, and use the authenticated availability mutation. Code and price remain immutable. Disconnecting a wallet restores the GitHub browser session; signing out revokes that browser session. HttpOnly session credentials cannot be copied as MCP credentials.

Free MCP credentials can be created from a GitHub session with `POST /v1/account/credentials`; no wallet is required. Choose a 1-hour, 1-day, 7-day, 30-day, or 90-day expiry (the API defaults to one hour). These credentials contain only free-use scopes already held by the parent session. The GitHub identity binding prevents paid quotes, and the browser cookie is never copied or returned.

## API keys

The API keys tab creates named keys, lists metadata, and removes keys by revoking the underlying credential. Full secrets are returned once on creation and stored only as hashes. `GET /v1/account/credentials` excludes browser sessions and token material; `POST /v1/account/credentials/{id}/revoke` checks ownership and immediately invalidates authentication. Only GitHub browser sessions can manage keys. Issued API keys cannot list, create, or revoke other keys. The account permits up to 100 unrevoked keys, including expired keys that can be removed. Existing free-agent credentials are adopted by the metadata migration.

GitHub accounts can upload Wasm artifacts and publish zero-price capabilities and workflows without a wallet. Paid publication requires a payout wallet. Existing browser sessions receive free-publishing permissions automatically; existing API keys retain their original scopes, so issue a new key for agent publication.

Publisher details and invocation counts use a batched `/v1/catalog/metadata` query. Verification is an administrator-controlled database flag, independent from GitHub identity and artifact sandbox validation. Account profiles cannot set it. Sidebar avatars use the saved profile. The header reads the current free tier and available hosted build credits from `/v1/account/plan`; these credits are separate from wallet funds.

Activity refreshes every three seconds while open and supports older-history pagination. GitHub browser sessions see calls across all their credentials, including revoked keys. Scoped API keys retain credential-only receipt/history access. Activity includes capability names, named credentials, timestamps, totals, and optional caller-reported model/harness context. Clients can send `x-hive-model`, `x-hive-agent`, and `x-hive-harness`; MCP also accepts `_meta["hive/client"]` fields and modern clientInfo names. Metadata is bounded, unverified client reporting. Historical missing metadata remains unknown. Read-only browser receipt access covers owned API-key calls; reconciliation and payment mutation stay credential-scoped.
